## Design Specificity Verdict

**LLM assessment** — Genuinely authored for this product, and the skin now carries some of that character. The IA, data model, and copy encode real PIC judgement: a roadmap-first work screen, "Siap berangkat / Pulang tuntas" cross-check gates, wallet flow (Bank/QRIS/Kas/E-Money), budget-vs-realisasi per component, and dana-cair tracking. An unrelated product could not reuse it unchanged. On the visual layer, the prior run's main complaint was resolved: the body face moved to **Public Sans** and the display face to **Big Shoulders Display**, a condensed agency/dispatch-board face that fits the "papan tugas dinas" theme far better than the previous overused-sans look. What is still generic is the *arrangement*: black hero with a giant percentage, black stat cards, red-on-white pill accents, and uppercase micro-labels is the default "bold dashboard" composition — product-specific in content, category-typical in layout.

## Overall Impression

A deeply considered, domain-true tool that is now visibly more disciplined than the previous critique found — context-preserving reload scaffolding, undo toasts, a grouped nav, and a guided work screen all landed. The biggest opportunity is to finish those jobs: the context-preservation code was written and then silently disabled, undo coverage is half-applied, and the work screen is calmer but still all-at-once.

## What's Working

- **Product-true workflow modelling.** Cross-check gates (`berangkatOk`/`pulangOk`), `epAnomali`, `stokSisa`, and budget-vs-realisasi derivation encode real PIC judgement, not generic CRUD. `store.financeSummary` is the spine.
- **A real accessibility pass landed.** `ui.modal` now sets `aria-modal="true"`, traps Tab, and restores focus (`ui.js:122-168`); nav items carry `aria-current="page"` (`app.js:31`); focus-visible outlines and `prefers-reduced-motion` are handled (`css/styles.css:175-185`). This is a large jump from the prior run.
- **Guided work screen and honest signalling.** The hero's "Langkah berikutnya" CTA, the numbered flowbar, the folded "Cek Persiapan", and the print-specific `printHTML` all set accurate expectations and reduce hunting.

## Priority Issues

- **[P1] The context-preserving reload was written and then overwritten.** `app.js:129` defines `A.reload` to capture the open accordion, re-render, re-apply it, and restore scroll — then `app.js:200` reassigns `A.reload = function () { render(); };`, so the first version (and `captureAccordion`/`applyAccordion`/`carryValues`) is dead. Every mutating action in `actions.js` calls `A.reload()`, so a toggle or save re-renders the whole work screen, resets which sections were open/closed, and drops any typed-but-unsaved fields in other sections. Why it matters: on a multi-section work screen this is the difference between "quick toggle" and "lost my place." Fix: delete the line-200 reassignment (or fold the scroll/accordion/field logic into it). Suggested command: `/impeccable harden`
- **[P2] Undo coverage is inconsistent.** `undoDelete` powers deletes for master items, transport, milestones, attachments, kas adjustments, dana cair, and event products — but `sale:delete`, `expense:delete`, `prepitem:delete`, and `budget:delete` (`actions.js:456,472,401,370`) fire a plain toast and permanently drop the row. Users learn "delete is undoable here" and are then burned. Why it matters: destructive-action expectations must be uniform or the safe cases stop feeling safe. Fix: route every destructive delete through `undoDelete` (or use `ui.confirm` uniformly where undo is impractical). Suggested command: `/impeccable harden`
- **[P2] The work screen still asks for everything at once.** Even folded, one view stacks the hero (progress + checks + next-step + 4 CTA buttons), a foldable 24-item "Cek Persiapan", an 8-pill flowbar, and 8 numbered sections. The "next section" defaults open, which helps, but the flowbar labels (`05 Penjualan`, `06 Kas`, `07 Pulang`, `08 Laporan`) still read as an undifferentiated row of eight. Why it matters: a first-timer scanning "what do I do next" must parse chrome before content. Fix: consider letting the flowbar show progress state per step (done/current/locked) or collapse steps beyond the current one behind "show all". Suggested command: `/impeccable distill`
- **[P2] Accessibility gaps that the detector cannot see.** The eight work sections render their titles as `<span class="psec-title">` (`pages2.js:280`), not headings — screen-reader heading navigation finds nothing in the work screen. The segmented tabs carry `role="tab"`/`aria-selected` but no `role="tabpanel"` link and no arrow-key handling (`pages.js:176-183`), and the mobile menu button (`index.html:41`) has `aria-label="Menu"` but no `aria-expanded`/`aria-controls`. Why it matters: Sam can operate the page but cannot jump by heading or trust the tab semantics. Fix: make each `psec-title` an `h2`/`h3` (or add `role="heading"` + `aria-level`), wire tabpanels and arrow keys, and expose the mobile menu state. Suggested command: `/impeccable audit`
- **[P3] Detector flags and two stray classes.** The `side-tab` left border on `.roadmap-phase` (`css/styles.css:237`) is the live detector finding; decide deliberately whether the roadmap rail earns it. Separately, nav group labels are `font-size: 10px` (`css/styles.css:35`) — below the 11px functional-text floor, and the detector missed it because it only reads the CSS declaration. Two typo'd classes also survive: `class="label hands"` and `class="btn btn-inks ..."` (`pages.js:473,480`); `btn-inks` is undefined, so that "Cetak Laporan" button silently loses its intended background. Fix: raise the nav label to 11px, confirm or drop the roadmap left border, and correct `btn-inks`/`hands`. Suggested command: `/impeccable polish`

## Persona Red Flags

**Alex (Power User)** — No keyboard shortcuts anywhere (only Esc/Tab inside a modal). Bulk multi-select exists for prep items via `A.bringSel`, but sales and expenses are strictly one row at a time. Because of the `A.reload` override (P1), toggling a checklist item re-renders the whole screen and collapses sections Alex had opened — the exact "I lost my place" friction the code claims to prevent.

**Sam (Accessibility-Dependent)** — Good progress: modal focus is trapped and restored, nav exposes `aria-current`, and focus-visible outlines exist. Remaining blockers: the eight work sections have no heading semantics (`pages2.js:280`), so heading-based navigation lands on almost nothing; `tabseg` advertises `role="tab"` without a `tabpanel` or arrow-key support; the mobile menu toggle (`index.html:41`) never announces expanded/collapsed state.

**Jordan (First-Timer)** — The rename to "Produk Dagangan" / "Barang Bawaan" and the grouped nav fixed the worst naming collision. Still shaky: "rekap tuntas", "Aset Jual", and the hero's "Progres persiapan" (which actually measures *milestones*, not prep items) require reading the FAQ to interpret, and the first meaningful action is still Dashboard → Event & Tugas → open event → find the right section.

## Minor Observations

- **Dead code / duplication:** `tabRoadmap` and `tabRingkasan` (`pages.js`) and `tabPersiapan`/`tabUang` (`pages2.js`) are exported but no longer routed; `tabRoadmap` duplicates the `ckSection` checklist blocks. Two progress-bar implementations persist (`ui.progress` vs local `progressBar` in both page files).
- **`STATUS_MAP` still maps both `berjalan`→"Berjalan" and `aktif`→"Berjalan"** (`ui.js:42-51`), which can mislabel status filters.
- **Print output remains a genuine strength:** `printHTML` is clean, print-specific, and now includes budget-vs-realisasi and per-wallet tables — keep it intact through refactors.
- **Empty states are consistently handled** via `ui.empty`, and forms use explicit `for`/`id` labels in most places.
